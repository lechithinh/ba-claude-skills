# Regulatory touchpoints (topics to ask about)

> **Last reviewed:** 2026-11 · **Status:** community draft, needs review by a payments compliance expert.
> This file lists **topics to raise with Compliance/Legal**, not legal conclusions or citations. Rules for payment intermediaries and wallets change often: always verify the current regulation, effective date and the provider's licence conditions.

| Topic | What a BA should check |
|---|---|
| Licensing of payment intermediary services (e-wallet, gateway) | Which activities need a licence; what the partner's licence permits |
| Identification and wallet limits | Verification levels, balance and transaction limits per level, eKYC requirements |
| Safeguarding customer funds | Where float is held, segregation, reporting |
| Anti-money laundering | Customer due diligence, monitoring, suspicious transaction reporting, record retention |
| Personal data protection | Consent, purpose, sensitive data, cross-border transfer, breach handling |
| Card data security | Scope of card data handling and tokenization (PCI DSS) |
| Authentication for online payments | Strong authentication requirements by amount or risk |
| Merchant onboarding | Business verification, prohibited merchant categories |
| Consumer protection and disputes | Complaint handling time limits, refund obligations |
| Tax and invoicing | Fee invoices, e-invoice rules |

## International standards
PCI DSS (card data) · ISO 20022 (messages) · EMV and 3-D Secure (card authentication) · OWASP MASVS (mobile app security).

## Turn into requirements
Add explicit compliance requirements with owner and sign-off date; keep limits, thresholds and windows configurable so a regulatory change is a parameter change.
